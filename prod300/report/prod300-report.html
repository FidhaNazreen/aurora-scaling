Aurora Prod300 Agent Run

300 chorismate mutase cases ran in one 12-hour prod pilot, each driven by its own Codex SDK agent on its compute node. A 256-node pilot queued as a backup started 2 h before the end and took over the waiting work. 85 cases reached a converged mechanism and 82 more finished with a diagnostic barrier. Every one of the 4,274 agent turns completed. The node and GPU numbers below describe this test's setup, not Reactra's production throughput: see the note.

How to read the utilization numbers

This run was set up as one case per node: each of the 300 cases was its own Reactra campaign with one run, on a site with nodes_per_job: 1, and each case's agent ran on its own GPU node. Reactra already packs up to 12 light-stage runs onto one node, but only within a campaign; with one run per campaign it had nothing to pack, so every light stage held a whole 12-tile node. The release, golden-2026-11-17j (Reactra 64b98b4, 17 Nov), was also a few days behind the latest packing improvements (18–21 Nov) and the reactra-hpc fleet runtime, but those were refinements: the one-case-per-campaign setup was the main cause. In production, with runs packed onto shared nodes, Reactra reaches 99.8% node occupancy and 94–96% GPU tile utilization on Aurora. The agent results stand; the node limit and the 45% GPU figure are effects of this setup.

What each case got

  • Converged barriers: energetic span median 73.8 kJ/mol (range 48.6–97.5), standard error median 0.33 kJ/mol. 80 came from each case's original run (kept-structure), 5 from agent relaunches.
  • Diagnostic: the run succeeded but failed at least one gate. Replicate profiles disagreed in 61 runs, the two string chains disagreed in 47, time slices in 14, coverage in 3, the covalent graph in 2 (a run can fail several).
  • Unfinished: still active when the last pilot ended. 60 were in or waiting for the 4-node reaction-sampling stage, 13 still in light stages. 58 of the 73 were agent relaunches that started late.
  • No result: every run failed and the agent deferred the case with a recorded next step. Most are umbrella windows that leave the reactive channel at the crest after 2 re-seeds (scientific refusal in reaction sampling); a few are repeated stalls in string relaxation.

  • The 300-node pilot was full from start to end. Tickets held 3,316 of its 3,556 node-hours (93%), and 2,894 of those were 4-node reaction-sampling tickets. At 01:30 UTC, 95 tickets were waiting for nodes.
  • The 256-node pilot never filled. It started at 05:20 UTC, when 25 tickets were waiting, and cleared that queue within a minute. It peaked at 117 busy nodes and gave idle nodes back to PBS after 10 minutes. Tickets used 274 node-hours on it, but released nodes are still charged, so it cost about 1,450 node-hours (256 × 5.65 h). Queuing it as a backup was a mistake. After the 300-node pilot ended at 07:17 it carried on with the runs that had been cut off, until 10:58.
  • GPU use reflects the one-case-per-node setup. 45% mean on the 300-node pilot, with 10-minute peaks of 74%; 28% on the 256-node pilot. A light-stage case held all 12 tiles of its node while using one, and each reaction-sampling ticket asked for 4 nodes under this release's sizing rule. Production packing reaches 94–96%.

Sampling started 6 h into the run, when the logger was added (22,685 node samples over both pilots). CPU stayed between 4% and 6% and memory between 16 and 78 GiB per node, with about 3 Codex processes per node.   • Tokens: 999M input (600M cached) and 11.5M output, median 97k input per turn. Drive250 used about half that in one hour; prod300 ran 12× longer, because agents were woken only on outcomes and every 30 minutes.
  • Actions through act: 113 relaunches, 200 submits, 52 retries, 166 checkpoints. 102 cases were relaunched at least once, 20 retried. The caps (2 relaunches, 3 retries per case) held.
  • Passes: the driver script ran 27,135 campaign passes, one per case every 5 minutes. Agents ran none, so no pass was cut short and no extra pilot was requested.
  • No unresolved or overridden decisions. No agent tried to defer an active run, and no outcome repeated after a decision.

What to change next time

  • Stop forcing one case per node. Put cases where Reactra can pack them: one shared campaign or the reactra-hpc fleet runtime, so light stages share nodes (12 per node) and reactive sampling repacks onto full nodes.
  • Run agents off the GPU nodes. One lightweight CPU-only agent per enzyme, each submitting into the same shared pilot pool. The driver design here (scripted passes, act with caps, blocked submit commands, guard) carries over unchanged.
  • Use the current release. This run used a 17 Nov release; further packing improvements landed 18–21 Nov.
  • Don't queue backup pilots. Released nodes are still charged for the whole request, so a backup that starts late costs its full size.
  • Look at the gate failures. Replicate-profile and chain-agreement failures kept 82 finished cases from converging; more sampling or a third chain may convert many of them.
